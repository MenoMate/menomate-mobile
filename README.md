# MenoMate Mobile

The official mobile client for **MenoMate** — an intelligent, privacy-first companion app for menstrual cycle tracking, menopause transition support, symptom logging, and connected wearable therapy. Built with **Flutter**, **Riverpod**, and **Drift (SQLite)**.

---

## 1. Overview

MenoMate Mobile is designed with an **offline-first** architecture. Users can seamlessly track symptoms, review history, receive deterministic daily wellness insights, and interact with the ESP32 wearable without requiring constant internet connectivity. When online, the app synchronizes securely with the [MenoMate Core Backend](https://github.com/MenoMate/MenoMate_core) over authenticated HTTPS endpoints.

### Key Capabilities
- **Server-Authoritative Cycle Tracking**: Clean visual cycle ring, phase status, and predictive intervals calculated by the backend and cached locally.
- **Offline-First Daily Logging**: Fast, local tracking for flow intensity, pain levels, mood indicators, and comprehensive symptom categories.
- **Deterministic Daily Insight**: Evidence-based daily insights and actionable suggestions powered by an internal, fully offline deterministic library.
- **Contextual Care Assistant**: Real-time conversational health guidance with automated emergency red-flag triage and structured follow-up actions.
- **Health Context & Treatment Tracking**: Dedicated profile management for medical background, chronic conditions, and active medications.
- **ESP32 Wearable Management (BLE)**: Bluetooth Low Energy discovery, device pairing, and deterministic thermal/vibration therapy profile dispatch.
- **Dual Visual Theme System**: Carefully crafted, accessible visual styles — **Sakura** (light) and **Starry Night** (dark).

## 2. Architecture & Data Flow

```text
               User Interface (Screens & Widgets)
                               │
                               ▼
               State Layer (Riverpod Providers)
                               │
                               ▼
                      Repository Layer
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
       Local SQLite (Drift)           FastAPI Remote API
      (Immediate reads/writes)        (Dio + JWT Bearer)
               │                               │
               └───────────────┬───────────────┘
                               │ (Sync on reconnect)
                               ▼
                   ESP32 Wearable (BLE)
```

### Responsibility Boundaries
1. **No Client-Side Prediction Math**: The mobile client displays and caches predictions generated by MenoMate Core. There is deliberately no duplicate prediction engine in Dart.
2. **AI Is Not a Hardware Controller**: Guidance received from the Care assistant is purely informational. Actuator commands are strictly governed by deterministic, safe therapy bounds.
3. **BLE Protocol Isolation**: All Bluetooth UUIDs, packet structures, and characteristic operations reside strictly within the device service layer — UI screens never manipulate raw BLE bytes directly.

## 3. Core Feature Specifications

### A. Cycle Ring & Predictive Display
- Displays cycle status, menstrual day, cycle phase, and predicted next period.
- Supports retrospective period closure with device-local date selection.
- All predictions display their associated confidence level (`low`, `moderate`, `high`) and state (`upcoming`, `today`, `awaiting_next_start`).

### B. Daily Wellness Logger
- **Flow Tracking**: Qualitative descriptors (spotting, light, medium, heavy).
- **Pain Scoring**: Visual slider (0 to 10 scale).
- **Mood Indicators**: Multi-select emotional wellness tokens.
- **Symptom Taxonomy**: Comprehensive symptom categorization kept in exact synchronization with the backend catalog.

### C. Daily Insight Library
- Fully offline and deterministic (`lib/content/insight_library.dart`).
- Maps the user's current cycle context (phase and day) to an evidence-backed insight paired with a practical action item.
- Operates instantaneously without network round-trips.

### D. Offline-First Synchronization
- **Transport States (`DataState`)**:
  - `Fresh`: Verified by a successful server round-trip.
  - `Cached`: Displaying local database state while remote is unreachable.
  - `PendingSync`: Changes saved locally, queued for upstream synchronization.
  - `Unavailable`: No local data exists and the server is unreachable.
  - `ConflictState`: Server flagged an entry requiring user review.
- **No-Account Offline Mode & Data Adoption**: Users can start tracking immediately without an account (`offline-local`); when they later sign in or create an account, an optional adoption flow moves local records into their cloud account safely.
- **Manual Sync Trigger**: Signed-in users can also trigger an immediate sync from Settings (**Sync data now**) in addition to automatic startup, sign-in, and reconnect sync passes.
- Writes apply to local SQLite immediately. When connectivity resumes, queued records synchronize upstream in FIFO order.

### E. Wearable & BLE Integration
- Communicates directly with the **ESP32 MenoMate Wearable** over Bluetooth Low Energy.
- Supports peripheral discovery, connection state management, and device pairing.
- Dispatches bounded therapy profiles (thermal intensity and vibration frequency) to manage acute symptoms like hot flashes and cramping.

## 5. Local Development Setup

### Prerequisites
- **Flutter SDK**: 3.24.x or higher (Dart 3.5+)
- **Android SDK & Build Tools** (for Android emulation or physical deployment)
- **Xcode** (optional, for macOS/iOS development)
- A running instance of [MenoMate Core Backend](https://github.com/MenoMate/MenoMate_core) or a reachable deployment

### Getting Started

```bash
# 1. Clone the repository
git clone https://github.com/MenoMate/menomate-mobile.git
cd menomate-mobile

# 2. Install dependencies
flutter pub get

# 3. Generate Drift database code (if modifying schema)
dart run build_runner build --delete-conflicting-outputs
```

### Running the App

#### Against Local Backend:
If running against a local backend on your computer via USB debugging:
```bash
# Forward backend port to connected Android device
adb reverse tcp:8000 tcp:8000

# Launch debug build
flutter run --dart-define=API_BASE_URL="http://127.0.0.1:8000" \
            --dart-define=SUPABASE_URL="https://your-project.supabase.co" \
            --dart-define=SUPABASE_ANON_KEY="your-anon-key"
```

#### Against Production Backend:
```bash
flutter run --dart-define=API_BASE_URL="https://menomate-core.onrender.com" \
            --dart-define=SUPABASE_URL="https://your-project.supabase.co" \
            --dart-define=SUPABASE_ANON_KEY="your-anon-key"
```

*(Pre-configured debug targets are also available in `.vscode/launch.json` for one-click debugging).*

## 7. Production Releases

MenoMate uses release-hardened configuration injection. No secrets or dynamic credentials are hardcoded into compiled binaries.

### Building the Android Release APK

```powershell
flutter build apk --release `
  --dart-define=API_BASE_URL="https://menomate-core.onrender.com" `
  --dart-define=SUPABASE_URL="https://your-project.supabase.co" `
  --dart-define=SUPABASE_ANON_KEY="your-anon-key"
```

*(Optional: Add `--split-per-abi` to compile optimized, smaller APKs per device architecture).*

The completed installer will be output to:
```
build/app/outputs/flutter-apk/app-release.apk
```

> **Platform Support**: MenoMate Mobile targets **Android** and **iOS** (local persistence uses native SQLite FFI via `drift/native.dart`). Web builds are not currently supported.

## 8. Runtime Configuration Reference

All sensitive parameters arrive via `--dart-define` environment flags during build or launch:

| Define Name | Mandatory in Release | Purpose | Default / Fallback |
| :--- | :---: | :--- | :--- |
| `API_BASE_URL` | No | Base URL of MenoMate Core API | `https://menomate-core.onrender.com` (Release) / `http://127.0.0.1:8000` (Debug) |
| `SUPABASE_URL` | **Yes** | Supabase project endpoint for Auth & JWKS | Must be passed at build time |
| `SUPABASE_ANON_KEY` | **Yes** | Public client anonymous API key | Must be passed at build time |

> **Safety Guard**: If an APK is launched without the required Supabase configuration, the app displays a graceful connection setup screen rather than crashing before the first frame.
